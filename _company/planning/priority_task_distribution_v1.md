# 우선순위 작업 분배 계획 v1.0\n\n## 🎯 핵심 우선순위 작업\n**작업명:** 데이터 수집 PoC 환경 구축 및 Relevance Score Model 초기 검증\n\n**목표:** 확정된 DB 스키마 및 분배 계획을 기반으로, 실제 타겟 기관의 데이터를 성공적으로 추출하고, 정의된 Relevance Score Model의 초기 유효성을 검증한다.\n\n## 👥 에이전트 및 역할 분배\n\n### 1. 코다리 에이전트 (Execution)\n*   **역할:** 확정된 기술 분배 계획(모듈별 설계, API/크롤링 정의)을 기반으로, **PoC를 위한 초기 데이터 수집 환경 및 템플릿**을 실제로 구현한다. (Phase 1)\n*   **산출물 목표:** PoC 환경에서 특정 타겟 기관의 샘플 데이터를 성공적으로 추출하고, DB 스키마와 매핑되는지 검증하는 초기 데이터 흐름(Pipeline) 확정.\n*   **필요 입력:** PostgreSQL DB 스키마 최종 확정본, 모듈별 API/크롤링 템플릿.\n\n### 2. Researcher 에이전트 (Validation)\n*   **역할:** 코다리가 구현한 PoC 결과물(데이터 추출 성공 여부, 수집된 데이터의 질)을 바탕으로, **Relevance Score Model**이 실제로 타겟 기관의 요구사항에 부합하는지 검증하고, 모델 가중치 조정에 필요한 구체적인 피드백을 제공한다. (Phase 2)\n*   **산출물 목표:** PoC 데이터에 대한 Relevance Score 산출 결과 및 모델 개선을 위한 구체적인 가중치 조정 제안.\n*   **필요 입력:** 코다리가 제공하는 PoC 추출 데이터 샘플, Relevance Score Model v1.0 가이드라인.\n\n## 🔄 작업 흐름 (Workflow)\n1.  **코다리:** 기술 구현 및 PoC 환경 구축.\n2.  **[보고]**: 코다리 → Researcher에게 PoC 결과물(샘플 데이터, 추출 성공률) 보고.\n3.  **Researcher:** PoC 결과 분석 및 Relevance Score Model 검증/피드백 제공.\n4.  **[반복]**: Researcher의 피드백을 바탕으로 코다리가 템플릿 및 로직 수정 후 재실행.\n\n## ✅ 성공 기준 (Success Criteria)\n*   PoC 환경에서 최소 1개 타겟 기관의 핵심 데이터를 성공적으로 추출할 수 있어야 함.\n*   Researcher가 제시한 Relevance Score 조정안이 논리적으로 타당해야 함.\n\n📝 다음 단계: 코다리 에이전트에게 PoC 실행을 위한 **'타겟 기관별 샘플 데이터 요청 시나리오(Mock Request)'**를 즉시 설계하도록 지시합니다.
