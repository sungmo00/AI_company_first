### 2. 기관별 구체적인 접근 경로 초안 및 평가

각 타겟 기관에 대해 연구과제 데이터 수집을 위한 가장 효율적인 경로(API, 공개 데이터 포털, 웹 크롤링 전략)를 초안하고, 그에 따른 실현 가능성을 평가합니다.

| 타겟 기관 | 접근 경로 초안 (기술적 방법) | 데이터 수집 상세 시나리오 (Step-by-Step) | 실현 가능성 평가 (1~5점, 5점: 매우 높음) | 주요 난이도 및 제약사항 |
| :--- | :--- | :--- | :---: | :--- |
| **1. MSIT** | **API 우선 접근:** 정부 정책/사업 공고 API 활용 (예: NTIS 연동 여부 확인) | 1. MSIT 공식 사업 공고 API 엔드포인트 식별. 2. 특정 키워드(AI, 융합)로 필터링 테스트. 3. 공개 데이터 포털(Data.go.kr) 연동 가능성 검토. | 4/5 | API 접근 권한 및 데이터 포맷의 비표준화 가능성. |
| **2. MOTIE** | **웹 크롤링 (정형화된 공고 페이지):** 사업 공고 게시판 HTML 구조 분석 및 정기적 스케줄링 크롤러 설계. | 1. MOTIE 사업 공고 페이지 URL 추출 로직 개발. 2. 과제명, 담당 부서 정보를 추출하기 위한 CSS 선택자 정의. 3. 주기적 데이터 수집 스케줄링 검토. | 3/5 | 웹페이지 구조 변경에 취약함. 크롤링 시 IP 차단 위험 존재. |
| **3. NRF** | **특화된 연구재단 포털 API:** 연구비 지원 현황 관련 데이터 제공 여부 확인. | 1. NRF 연구과제 DB 접근 권한 및 API 문서 검토. 2. 과제 유형별 분류 체계 매핑. 3. 연구비 집행 현황 데이터 수집 모듈 설계. | 4/5 | 내부 시스템 접근 제한 가능성 (로그인 필요). API 문서의 상세함에 따라 난이도 변화. |
| **4. MSS** | **공개 데이터 포털 연동:** 중소기업 지원 사업 공고 목록 및 관련 통계 자료 수집. | 1. MSS 사업 공고 DB 검색 인터페이스 확인. 2. 지원 대상(중소기업 기준) 필터링 로직 구현. 3. 사업 완료/진행 단계 추적 데이터 확보 방안 검토. | 3/5 | 정보의 분산 정도 (여러 부처 연계)로 인해 통합 데이터 수집의 복잡성 증가. |
| **5. 출연연 A** | **직접적인 협의/공식 요청 (API 비효율):** 연구원 또는 산학협력단과의 직접 소통 채널 확보. | 1. 해당 출연연의 공식 웹사이트 내 '협력/문의' 채널 확인. 2. 연구원 대상 간접 인터뷰 또는 공식 자료 요청 프로세스 설계. | 2/5 | 자동화(Automation)가 극히 어려우며, 수동 개입 빈도가 높음. |

### 3. 실현 가능성 종합 분석 및 권고 사항 (AMS 가중치 적용)

| 평가 항목 | 분석 결과 요약 | Researcher 권고 및 전략 방향 |
| :--- | :--- | :--- |
| **전반적 실현 가능성** | 4/5 수준으로, 공공기관 데이터는 API 기반 접근이 가장 효율적이나, 기관별로 접근 방식(API vs. 크롤링 vs. 수동)이 크게 다름. | **단계적 접근 전략(Phased Approach)**을 채택해야 함. 1순위 타겟(MSIT, NRF)에 리소스를 집중하고, 2순위 기관은 크롤링 안정성 테스트를 선행해야 함. |
| **가장 큰 제약 요소** | 출연연(타겟 5번)과 같이 비정형화된 데이터 소스는 자동화에 가장 큰 제약을 가함. | **수동 개입 최소화 전략:** 출연연 접근 시, 초기에는 정기적인 수동 리서치로 **'골든 데이터 포인트(Golden Data Point)'**를 확보하는 데 집중해야 함. |
| **AMS 가중치 제안** | API/공식 데이터 기반 접근에 높은 가중치를 부여하고, 비정형 데이터(5번)에는 낮은 가중치로 초기 리소스 투입을 제한해야 함. | **API/정형 데이터 수집 모듈 개발에 60%의 리소스**를 투입하고, 나머지 40%는 크롤링 및 수동 검증에 할애할 것을 제안함. |

**결론:**
최우선 타겟 5개 기관에 대해 **API/공식 데이터 접근을 최우선**으로 설정하고, 각 경로별로 **데이터 추출 난이도와 안정성을 정량적으로 비교**하는 것이 효율적입니다. 현재 초안은 '어디서 찾을 수 있는지'에 대한 청사진이며, 다음 단계에서는 **Developer 에이전트와 협력하여 해당 경로의 실제 기술적 구현(Schema 매핑, 크롤링 로직)에 착수**해야 합니다.
