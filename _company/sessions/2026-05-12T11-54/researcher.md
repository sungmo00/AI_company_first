### 2단계: 승인 패키지 기술 요구사항 명세 초안 확정

**결과물:** **Phase 1 실행을 위한 V2.0 기술 요구사항 명세 초안**

다음은 검증 결과를 반영하여, 개발팀이 즉시 구현에 착수할 수 있도록 구체화한 기술 요구사항 명세 초안입니다.

#### 1. 데이터 모델 및 스키마 (Schema Definition v1.1)
*   **목표:** 연구과제 정보 수집, 경쟁사 활동 분석을 위한 데이터 구조를 확정합니다.
*   **주요 변경 사항:** 기존 13개 컬럼 외에, **'Source Reliability Score (SRS)'** 및 **'NLP Feature Vector'** 필드를 추가하여 데이터 품질 관리의 기준을 강화합니다.
    *   `Source Reliability Score (SRS)`: 데이터 출처의 신뢰도를 0.0에서 1.0 사이로 정량화하는 필드. (평가 기준: 공식 웹사이트 직접 정보 vs. 3rd Party 요약본).
    *   `NLP Feature Vector`: 비정형 텍스트(예: 연구 제안서 요약, 경쟁사 뉴스 기사)에 대한 임베딩 벡터를 저장할 필드. (기술 스택: BERT 기반 모델 필요).

#### 2. 핵심 데이터 추출 모듈 (Extraction Module Specification)
*   **목표:** 정부 및 공공기관의 비정형/정형 데이터를 안정적으로 수집하는 모듈을 설계합니다.
*   **API Endpoint 명세 (예시):**
    *   `GET /api/gov/projects?기관코드={code}&기간={start}&분야={field}`: 특정 기관의 연구과제 목록 조회. (응답 형식: JSON 표준화 필수).
    *   `POST /api/competitor/analyze`: 경쟁사 콘텐츠 URL을 입력받아 핵심 키워드 및 톤앤매너 분석 요청. (기술 스택: 웹 크롤링 및 LLM 기반 텍스트 분석 모듈 통합).
*   **예외 처리 요구사항:** 외부 API의 응답 오류(4xx, 5xx) 발생 시, **최소 3회 재시도 로직**을 구현해야 하며, 실패 시 알림(Alert) 메커니즘이 트리거되어야 합니다.

#### 3. ALTIT 매칭 점수 (AMS) 가중치 모델 재설계
*   **목표:** 연구과제 매칭의 정확도를 높이기 위해 가중치 모델을 강화합니다.
*   **신규 가중치 구조:** 기존의 '연구 분야 연관성' 외에, 다음 두 요소를 독립적으로 반영하도록 가중치를 분리합니다.
    *   **Weight A (Relevance):** 목표 연구 분야와의 직접적인 기술적 연관성 (가중치 범위: 40-50%).
    *   **Weight B (Feasibility):** 해당 과제가 현재 ALTIT의 기술 스택 및 인력으로 수행 가능한 실현 가능성 (가중치 범위: 30-40%).
*   **구현 요구사항:** 이 두 가중치에 대한 입력 데이터 정의서(Input Data Definition Document)를 별도로 작성하여, 각 가중치 산출에 필요한 정량적 지표(Metrics)를 명확히 정의해야 합니다.
