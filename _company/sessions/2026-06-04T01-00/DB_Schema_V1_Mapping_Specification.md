# DB 스키마 V1 매핑 상세 명세 (초안)\n\n## 1. 개요\n본 문서는 Researcher가 정의한 연구과제 데이터 추출 SOP (수집-정제-매핑)의 각 단계별로, 최종 목표인 PostgreSQL DB 스키마 V1에 데이터를 매핑하기 위한 상세 로직 및 기술 요구사항을 정의합니다. 이 명세는 데이터 파이프라인의 설계 청사진 역할을 합니다.\n\n## 2. DB 스키마 V1 개요 (참조)\n(이 섹션에는 실제 DB 스키마 V1의 주요 테이블 정의를 삽입해야 합니다. 현재는 개념적 구조만 명시합니다.)\n\n**예시 테이블:**\n*   `projects`: 연구과제 메타데이터 저장 (ID, Title, Source_Agency\_ID, Status 등)\n*   `projects_details`: 상세 정보 저장 (project_id FK, Funding\_Amount, Submission\_Date 등)\n*   `sources`: 데이터 원천 정보 저장 (Agency\_ID, URL, Extraction\_Method 등)\n\n## 3. 단계별 매핑 로직\n\n### 3.1. 단계 1: 데이터 수집 (Acquisition) 매핑\n**입력:** 원시 데이터 (크롤링 결과, API 응답 JSON 등)\n**출력 목표:** `sources` 테이블과 임시 데이터 셋 생성\n**매핑 로직 상세:**\n1.  **기관 식별:** 수집된 데이터의 출처(웹사이트, API)를 기반으로 고유한 `Agency_ID`를 할당합니다. (매핑 기준: [Researcher의 타겟 기관 목록/코드])\n2.  **원시 데이터 구조화:** 수집된 JSON/HTML 구조를 분석하여, 최소한의 필수 필드(Title, Abstract, ID)를 추출합니다. 이 과정에서 데이터 누락 시 Flag를 지정합니다.\n3.  **Source 기록:** 추출된 원시 데이터와 함께, 해당 데이터의 출처 정보(URL, 수집 일시)를 `sources` 테이블에 초기 레코드로 기록합니다.\n\n### 3.2. 단계 2: 데이터 정제 (Refinement) 매핑\n**입력:** 단계 1에서 수집된 원시 데이터셋.\n**출력 목표:** `projects` 및 `projects_details` 테이블로의 정규화된 데이터 변환\n**매핑 로직 상세:**\n1.  **데이터 클렌징:** 텍스트 데이터(Title, Abstract)에 대한 정규화(불필요한 공백 제거, 특수 문자 처리)를 수행합니다. (규칙: [Researcher의 데이터 품질 KPI 적용])\n2.  **데이터 검증:** 필수 필드(예: Funding\_Amount)의 데이터 타입 및 범위 유효성을 검증합니다. (실패 시: 격리(Quarantine) 테이블로 이동)\n3.  **관계 구축:** 정제된 데이터를 기반으로 `projects` 테이블에 기본 정보를 저장하고, 상세 정보(`projects_details`)를 분리하여 관계(Foreign Key)를 설정합니다. (Mapping Logic: 1:N 관계 확립)\n\n### 3.3. 단계 3: 데이터 매핑 (Mapping) 최종 검증\n**입력:** 정제된 데이터셋.\n**출력 목표:** 최종 DB 삽입 준비 완료\n**매핑 로직 상세:**\n1.  **스키마 정합성 검사:** 모든 필드가 대상 테이블의 제약 조건(NOT NULL, UNIQUE 등)을 만족하는지 최종 확인합니다. (필수 검증: `lint_test` 모듈을 통해 로직의 일관성 확인)\n2.  **트랜잭션 설계:** 수집부터 최종 삽입까지의 전체 파이프라인을 단일 트랜잭션 또는 최소한의 원자적 단위로 묶는 방안을 설계합니다. (Developer 담당: 트랜잭션 관리 로직 정의)\n\n## 4. 기술적 요구사항 (Developer Action Items)\n*   **Schema Definition Generator 연동:** Pydantic 모델(`developer.md` 참조)이 이 매핑 로직을 기반으로, 데이터 수집 모듈에서 반환해야 할 최소/최대 필드 정의를 생성하도록 인터페이스를 설계합니다.\n*   **Transformation Layer:** 단계 2의 모든 클렌징 및 정규화 로직을 Python 함수/모듈로 분리하여, 향후 유지보수가 용이하도록 설계합니다.\n*   **Error Handling:** 각 단계별 실패 시, 로그 기록 및 알림(Notification) 메커니즘을 명세화합니다.\n\n이 초안에 대해 검토 후, Researcher와 협업하여 매핑 로직의 구체적인 구현 방안을 확정하겠습니다.<|"|>
