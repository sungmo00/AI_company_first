# 데이터 추출 프로세스 정의서 (SOP) 초안: 수집-정제-매핑 3단계 워크플로우

## 1. 개요
본 문서는 정부 및 공공기관의 연구과제 데이터를 수집, 정제, 그리고 ALTIT KOREA의 내부 시스템(DB 스키마 V1)에 맞게 매핑하는 전 과정을 정의하는 표준 운영 절차(SOP)의 초안입니다.

**목표:** 연구과제 데이터 추출부터 최종 시스템 반영까지의 명확한 작업 흐름을 확립하고, 각 단계별 책임(R&R)과 산출물 기준을 정의합니다.

## 2. 워크플로우 상세 (3단계)

### 단계 1: 데이터 수집 (Acquisition)
**목표:** 최우선 타겟 기관별로 연구과제 원시 데이터를 확보하는 단계.
**책임:** Researcher (주도), Developer (기술 지원)
**핵심 활동:**
1.  **타겟 기관별 접근 경로 실행:** Researcher가 정의한 '기관별/분야별 검색 가이드라인'에 따라 API 호출, 웹 크롤링, 또는 공식 문서 다운로드를 수행합니다.
2.  **데이터 추출:** 정의된 검색 쿼리 및 시나리오(Test Cases)를 실행하여 원시 데이터(Raw Data)를 확보합니다.
3.  **데이터 포맷 통일:** 수집된 다양한 형식의 데이터를 일관된 중간 포맷(예: JSON 배열)으로 변환합니다.
**산출물:** 원시 데이터셋 (Raw Dataset), 수집 시나리오 로그.
**성공 기준:** 정의된 5개 타겟 기관에서 최소 80% 이상의 필요한 연구과제 데이터를 확보하고, 데이터 추출 과정의 안정성이 검증됨.

### 단계 2: 데이터 정제 (Refinement)
**목표:** 수집된 원시 데이터를 분석 및 시스템 매핑을 위해 일관되고 신뢰할 수 있는 형태로 가공하는 단계.
**책임:** Business (품질 기준 정의), Researcher (가공 로직 지원)
**핵심 활동:**
1.  **데이터 정제:** 누락된 값(Null), 형식 오류, 중복 데이터 등을 제거하거나 보완합니다.
2.  **표준화:** 모든 필드의 데이터 타입, 단위(Unit), 명명 규칙을 ALTIT KOREA 내부 표준에 맞게 통일합니다. (예: 날짜 형식 통일, 텍스트 정규화)
3.  **품질 검증:** 데이터의 정확성과 완전성을 검증하는 품질 게이트(Quality Gate)를 설정하고 통과 여부를 판단합니다.
**산출물:** 정제된 데이터셋 (Clean Dataset), 데이터 품질 검증 보고서.
**성공 기준:** 정제된 데이터셋의 오류율이 1% 미만이며, 모든 필수 필드가 표준화 기준을 충족함.

### 단계 3: 데이터 매핑 (Mapping)
**목표:** 정제된 데이터를 PostgreSQL DB 스키마 V1의 요구사항에 맞게 변환하고, 비즈니스 로직(KPI 측정)을 반영하는 단계.
**책임:** Developer (주도), Researcher (매핑 로직 검토)
**핵심 활동:**
1.  **스키마 매핑:** 정제된 데이터셋의 필드와 DB 스키마 V1의 엔티티 및 필드를 1:1 또는 N:1로 매핑합니다.
2.  **ALTIT KOREA 로직 적용:** 핵심 요구사항인 'ALTIT 매칭 점수(AMS)' 가중치 계산 로직을 적용하여 최종 데이터셋에 점수를 부여합니다.
3.  **API Contract 검증:** 매핑된 데이터가 Developer가 설계한 API Contract를 준수하는지 최종적으로 검증합니다.
**산출물:** DB 적합 데이터셋 (Mapped Dataset), AMS 가중치 적용 로직 상세 문서, API Contract 검증 리포트.
**성공 기준:** 매핑된 데이터가 DB 스키마 V1의 모든 필수 제약 조건을 만족하며, AMS 계산 로직이 기술적으로 유효함.

## 3. 단계별 작업 분배 계획 (R&R)

| 단계 | 주요 활동 | 담당 에이전트 | 세부 분배 역할 | 최종 산출물 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 수집** | 타겟 기관 데이터 확보 및 원시 데이터 추출 | Researcher (주), Developer (보조) | 접근 경로 설계, 크롤링/API 호출 시나리오 작성 | 원시 데이터셋 |
| **2. 정제** | 데이터 품질 관리 및 표준화 | Business (주), Researcher (지원) | 품질 기준 정의, 데이터 정제 로직 검토 | 정제된 데이터셋 |
| **3. 매핑** | DB 스키마 V1 연동 및 비즈니스 로직 적용 | Developer (주), Researcher (검토) | DB 매핑, AMS 가중치 로직 구현 및 검증 | DB 적합 데이터셋 |

**다음 단계:** Researcher는 위 워크플로우 초안을 기반으로, 각 단계별로 필요한 **구체적인 데이터 요구사항(필수 컬럼 정의)**을 상세화하는 작업을 즉시 진행해야 합니다. Developer에게는 단계 3의 기술적 구현을 위한 초기 프레임워크를 요청할 준비를 합니다.
