# SOP 초안: 연구과제 데이터 추출 프로세스 (수집-정제-매핑 3단계)

## 1. 개요
본 문서는 정부 및 공공기관의 연구과제 정보를 수집, 정제, 그리고 내부 DB 스키마 V1에 매핑하는 전체 데이터 추출 프로세스의 상세 단계별 작업 분배 계획 및 각 단계의 성공/실패 기준(KPI 초안)을 정의한다.

## 2. 전체 워크플로우 개요
전체 프로세스는 다음 세 단계로 구성되며, 각 단계는 이전 단계의 산출물을 입력으로 사용한다.

**[단계 1: 데이터 수집 (Acquisition)]** $\rightarrow$ **[단계 2: 데이터 정제 (Refinement)]** $\rightarrow$ **[단계 3: 데이터 매핑 (Mapping)]**

## 3. 단계별 상세 작업 분배 및 기준

### 단계 1: 데이터 수집 (Acquisition)
**목표:** 정의된 타겟 기관별/분야별 가이드라인에 따라 비정형 데이터 소스에서 연구과제 원본 데이터를 확보한다.

*   **담당 에이전트:** Researcher (주도), Developer (API/크롤링 구현 지원)
*   **세부 작업:**
    1.  **타겟 경로 식별 및 목록화:** Researcher가 정의한 기관별/분야별 접근 경로(API 엔드포인트, 크롤링 규칙)에 따라 데이터 수집 대상 목록을 확정한다. (→ *Researcher의 가이드라인 활용*)
    2.  **데이터 추출 실행:** 확정된 경로에 따라 실제 연구과제 데이터를 수집한다.
    3.  **초기 데이터 포맷팅:** 수집된 원본 데이터를 최소한의 구조(JSON/XML)로 변환하여 다음 단계로 전달할 수 있도록 준비한다.
*   **성공/실패 기준 (KPI 초안):**
    *   **Success:** 목표로 설정된 타겟 기관별/분야별 **최소 $N$ 건의 유효한 원본 데이터**를 확보하고, 데이터 수집 경로의 **90% 이상이 안정적으로 작동**함을 확인한다.
    *   **Failure:** 핵심 타겟 기관의 데이터 접근 실패율이 50%를 초과하거나, 수집된 데이터의 형식 불일치율이 20%를 초과하는 경우.

### 단계 2: 데이터 정제 (Refinement)
**목표:** 수집된 원본 데이터를 표준화하고, 누락되거나 오류가 있는 데이터를 보완하여 분석 가능한 형태로 가공한다.

*   **담당 에이전트:** Researcher (주도), Developer (데이터 클렌징 로직 구현 지원)
*   **세부 작업:**
    1.  **데이터 표준화:** 수집된 데이터의 형식(날짜, 용어, 단위 등)을 내부 표준 스키마에 맞게 정규화한다. (→ *Researcher의 데이터 품질 관리 기준(KPI) 적용*)
    2.  **오류 검증 및 보완:** 누락된 필수 필드를 식별하고, 필요한 경우 추론(Inference) 또는 보완 작업을 수행한다. (→ *Developer의 오류 처리 로직 테스트 케이스 활용*)
    3.  **데이터 품질 검사:** 정제된 데이터에 대해 **데이터 품질 지표(Completeness, Consistency)**를 측정한다.
*   **성공/실패 기준 (KPI 초안):**
    *   **Success:** 정제된 데이터의 **데이터 일관성 지수(Consistency Score)가 95% 이상**이며, 필수 필드의 **누락률이 5% 미만**임을 입증한다.
    *   **Failure:** 정제 과정에서 발생하는 치명적인 데이터 손실(데이터 무결성 훼손)이 발생하거나, 정제된 데이터의 일관성이 기준치 미달인 경우.

### 단계 3: 데이터 매핑 (Mapping)
**목표:** 정제된 데이터를 내부 DB 스키마 V1의 요구사항에 맞게 정확하게 변환(매핑)하여 최종 데이터셋을 완성한다.

*   **담당 에이전트:** Developer (주도), Researcher (매핑 로직 검토 및 최종 승인)
*   **세부 작업:**
    1.  **스키마 매핑 로직 구현:** 정제된 데이터 필드와 DB 스키마 V1의 각 필드 간의 **Mapping Logic**을 구현한다. (→ *Developer가 설계한 mapping\_logic.py 활용*)
    2.  **ALTIT 매칭 점수(AMS) 적용:** 연구과제의 관련도 및 적합성을 평가하는 **ALTIT 매칭 점수(AMS) 가중치 로직**을 적용하여 최종 점수를 산출한다.
    3.  **최종 검증:** 매핑된 최종 데이터셋이 DB 스키마 V1의 제약 조건(데이터 타입, 필수 제약)을 완벽하게 만족하는지 최종 검증한다.
*   **성공/실패 기준 (KPI 초안):**
    *   **Success:** 최종 매핑된 데이터셋이 **DB 스키마 V1의 모든 제약 조건을 100% 만족**하며, **AMS 계산 로직이 요구사항에 따라 정확하게 작동**함을 검증한다.
    *   **Failure:** 매핑 과정에서 데이터 타입 불일치 오류가 발생하거나, AMS 계산 결과가 논리적으로 모순되는 경우.

## 4. 다음 단계
*   **Developer:** 단계 1 및 2의 산출물에 대한 기술적 연동(API/DB 인터페이스) 검증을 시작한다.
*   **Business:** 단계 2의 품질 관리 기준(KPI 초안)에 대한 최종 검토 의견을 제공한다.
