# 데이터 추출 프로세스 (SOP) 최종 명세서 및 워크플로우 확정

## 🎯 목표
ALTIT KOREA의 연구과제 데이터 수집 및 정제 파이프라인(ETL)에 사용될 전체 워크플로우의 **수집, 정제, 검증** 단계를 최종 확정하고, Developer 에이전트에게 명확한 기술 구현 가이드라인을 제공한다.

## 📝 범위
본 문서는 외부 소스(정부/공공기관 웹, API 등)로부터의 원시 데이터 수집부터 PostgreSQL DB에 최종적으로 로드(Loading)되기까지의 모든 단계를 정의한다.

## ⚙️ 최종 워크플로우 (3단계)

### Step 1: 데이터 수집 (Extraction Layer)
**목표:** 목표 기관별/분야별로 필요한 원시 데이터를 안정적으로 수집한다.

*   **1.1. 타겟 정의 및 경로 확정 (Input: Target_Source_Map.json):**
    *   최우선 타겟 5개 기관(예: 과기정통부, 특정 연구재단 등)별로 확정된 API 엔드포인트, 크롤링 대상 URL 목록을 최종 검토한다.
    *   **검증 항목:** 각 경로별 접근 권한 요구사항, 데이터 포맷(JSON/XML 등), Rate Limit 정책을 명시한다.
*   **1.2. 데이터 추출 시나리오 작성 (Step-by-Step):**
    *   각 타겟 경로에 대해, 성공적인 데이터 추출을 위한 **Step-by-Step 실행 시나리오**를 작성한다. (예: 요청 헤더, 파라미터 구성, 예상 응답 구조 정의)
*   **1.3. 추출 안정성 평가:**
    *   각 수집 경로에 대해 **데이터 추출 난이도 점수 (1-5)** 및 **안정성 지수 (High/Medium/Low)**를 할당한다. (Researcher 메모리 기반)

### Step 2: 데이터 정제 및 표준화 (Transformation Layer)
**목표:** 수집된 원시 데이터를 PostgreSQL DB 스키마 V1에 맞추어 일관성 있고 사용 가능한 형태로 변환한다.

*   **2.1. 데이터 유효성 검사 (Validation):**
    *   수집된 각 필드(Field)에 대해 **필수 여부, 데이터 타입 일치성, 형식 검증**을 수행한다.
    *   *(예시: 연구과제명 필드는 최대 길이 제한 준수 여부 검사)*
*   **2.2. 데이터 표준화 (Normalization):**
    *   비정형 텍스트(Text) 데이터를 정규화한다. (예: 기관명, 키워드 분류 체계 통일)
    *   날짜/시간 형식의 표준화 (UTC 기준).
    *   데이터 누락(Null) 처리 정책 정의: 필수 항목 누락 시 **'재시도 로직'** 또는 **'데이터 플래그 지정'** 중 하나를 선택하여 정의한다.
*   **2.3. 데이터 매핑 (Mapping):**
    *   Step 1에서 수집된 원시 필드 $\rightarrow$ PostgreSQL 스키마 V1의 최종 컬럼 매핑 테이블을 정의한다. (이 과정에서 데이터 손실 방지)

### Step 3: 데이터 로딩 및 검증 (Loading & Verification Layer)
**목표:** 정제된 데이터를 PostgreSQL DB에 안전하게 로드하고, 최종 데이터 무결성을 보장한다.

*   **3.1. DB 로딩 전략:**
    *   대용량 데이터 처리 시, 배치(Batch) 단위로 로딩할지 스트리밍 방식으로 진행할지 결정하고 그 전략을 명시한다.
*   **3.2. 데이터 무결성 검증 (Integrity Check):**
    *   로드 완료 후, **샘플 기반의 검증 쿼리 (Validation Query)**를 정의한다.
    *   **핵심 검증 기준:** 수집된 총 건수와 로드된 건수의 일치 여부, 주요 메트릭(예: 필수 필드 누락률)이 허용 오차 범위 내에 있는지 확인한다.
    *   **에러 로깅:** 검증 실패 시, 오류 발생 지점(Step 1 또는 Step 2)을 명확히 기록하는 로깅 메커니즘을 정의한다.

## 📊 최종 산출물 요약 (Developer에게 전달할 핵심)
이 명세서는 Developer가 다음의 세 가지 주요 모듈을 설계하고 구현하도록 지시하는 **'계약서'** 역할을 수행한다.

1.  **Extraction Module Spec:** Step 1 실행을 위한 API/크롤링 인터페이스 정의.
2.  **Transformation Module Spec:** Step 2의 유효성 검사 및 표준화 로직 구현을 위한 규칙서.
3.  **Loading Module Spec:** Step 3의 배치 처리 및 최종 무결성 검증 로직 구현을 위한 DB 연동 가이드.
