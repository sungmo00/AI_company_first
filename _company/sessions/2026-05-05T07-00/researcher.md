### 2. 세부 평가 및 전략 제언

#### A. 난이도 분석 (Difficulty Assessment)

*   **난이도 1-2 (Low):** 공개된 정적 데이터셋(CSV, XML)을 이용한 추출. 기술 구현은 비교적 단순하며, 데이터 수집의 안정성은 높으나, 데이터 변경 시마다 URL 구조가 바뀔 위험이 존재함.
*   **난이도 3 (Medium):** 표준화된 REST API를 이용한 추출. 인증(API Key/Token) 설정 및 응답 데이터 포맷(JSON/XML 변환) 처리가 필요함. 안정성은 중간 수준이며, API 변경에 따른 즉각적인 영향이 발생할 수 있음.
*   **난이도 4-5 (High):** 동적 웹페이지 크롤링(Selenium, Puppeteer) 또는 비공개/보안 수준이 높은 내부 시스템 접근. 구현 난이도가 높고, 기술적 안정성 확보를 위해 지속적인 유지보수 및 예외 처리 로직 구축이 필수적임.

#### B. 안정성 평가 (Stability Assessment)

*   **High Stability:** 정적 파일 다운로드 또는 매우 안정적으로 유지되는 공개 API. 데이터 수집 프로세스 자동화(Scheduling)에 용이함.
*   **Medium Stability:** 표준 API 사용. 중간 수준의 안정성을 가지며, 데이터 포맷이 변경될 경우 즉시 파싱 로직 수정이 필요함.
*   **Low Stability:** 동적 웹 크롤링 또는 인증 기반 접근. 시스템의 불안정성(로그인 실패, 세션 만료)에 취약하며, 외부 환경 변화에 가장 민감함.

### 3. 최종 권장 사항 (Actionable Insights)

1.  **우선순위 설정:** 데이터 수집의 초기 단계에서는 **난이도 2 (High Stability)** 경로(기관 C와 유사)를 최우선으로 확보하여 신속하게 초기 데이터 라이브러리를 구축해야 합니다.
2.  **기술 스택 분리:** 난이도 4-5 경로(기관 D와 유사)는 별도의 보안 및 인프라 검토를 거쳐야 합니다. API 호출 로직과 크롤링 로직을 분리하여 모듈화해야 향후 확장성이 확보됩니다.
3.  **데이터 무결성 (AMS 적용):** 모든 경로 확정 시, **'ALTIT 매칭 점수(AMS)' 가중치**를 적용할 수 있는 데이터 필드 정의를 해당 기관의 응답 스키마와 즉시 매핑하는 작업을 병행해야 합니다. (이 작업은 Secretary 에이전트와 협업하여 진행 필요)
