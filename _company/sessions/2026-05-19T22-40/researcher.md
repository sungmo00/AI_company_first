**[작업 개요]**
*   **목표:** 정부 및 공공기관의 연구과제 데이터를 체계적으로 수집하고 추출하기 위한 단계별 접근 경로(Data Source Access Path) 및 개념 증명(PoC) 계획을 포함한 로드맵 초안 작성.
*   **기준:** Researcher 개인 메모리 및 이전 세션에서 확정된 '최우선 타겟 5개 기관' 목록, 최종 컬럼 정의서(Schema Definition), 그리고 기술적 리스크 평가 결과를 기반으로 구조화.
*   **산출물 형태:** 단계별(Phase)로 구분된 상세 로드맵 문서. 각 단계는 '타겟 기관/분야', '접근 경로(API/웹)', '수집 방법론(크롤링/API 호출 시나리오)', 'PoC 목표 및 성공 지표', '예상 난이도/리스크 평가'를 포함해야 함.

**[작업 단계 및 실행 계획]**

다음은 로드맵 초안을 구성하기 위한 구체적인 3단계 실행 계획입니다.

**Phase 1: 타겟 기관별/분야별 검색 가이드라인 세부화 (Foundation)**

1.  **데이터 검토:** Researcher 개인 메모리 중 '최우선 타겟 5개 정부 및 공공기관의 구체적인 웹/API 접근 경로 초안' 및 '기관별/분야별 검색 가이드라인 초안'을 최우선으로 검토합니다. (참조: sessions/2026-05-05T08-32/researcher.md, sessions/2026-05-05T08-59/researcher.md)
2.  **프레임워크 설계:** 각 타겟 기관별로 연구과제 데이터가 존재하는 **핵심 검색 키워드, 필요한 인증/접근 방식(API Key 필요 여부), 데이터 구조 예상 형태**를 매핑하는 프레임워크를 설계합니다.
3.  **가이드라인 정교화:** 각 기관별로 '데이터 수집의 실효성 점수'를 기반으로 우선순위(High/Medium/Low)를 재조정하고, 데이터 추출에 필요한 **최소 요구사항(Minimum Viable Data Set)**을 정의합니다.

**Phase 2: 데이터 추출 모듈 PoC 계획 수립 (Execution Blueprint)**

1.  **스키마 매핑 검토:** Developer 에이전트가 정의한 `ResearchProjectSchema` (Pydantic 스키마)와 Phase 1에서 정의된 데이터 구조 간의 매핑 정확성을 최종 검토합니다. (참조: sessions/2026-05-05T08-45/researcher.md)
2.  **PoC 시나리오 정의:** Phase 1에서 우선순위가 높은 기관(Top Tier)을 대상으로, **실제 데이터 추출이 가능한지 검증**하기 위한 최소한의 PoC 시나리오를 작성합니다.
    *   PoC 목표: 특정 기관 A에서 연구과제 데이터 10건 이상 성공적으로 추출.
    *   PoC 방법론: API 호출 시나리오 기반 테스트, 비공식 웹 크롤링 테스트 등.
3.  **기술적 요구사항 구체화:** PoC를 수행하기 위해 필요한 **초기 환경 설정(예: Mock API Endpoint, 테스트 데이터 세트 확보 방안)**을 정의하고 Developer 에이전트에게 명확한 구현 지침을 전달할 수 있도록 준비합니다.

**Phase 3: 로드맵 최종 확정 및 리소스 할당 (Finalization)**

1.  **마일스톤 정의:** Phase 1과 Phase 2에서 도출된 모든 세부 작업(데이터 수집, PoC 검증, 스키마 조정)을 포함하여 전체 로드맵의 최종 마일스톤(Milestone)과 기한(Deadline)을 산출합니다.
2.  **리소스 및 리스크 평가:** 각 마일스톤별로 필요한 **인력(Researcher/Developer), 예상 소요 시간, 기술적 난이도(Complexity Score), 그리고 데이터 확보 실패 시의 대체 전략**을 최종적으로 산출하여 Business 에이전트에게 전달할 수 있도록 구조화합니다. (참조: sessions/2026-05-19T08-25/researcher.md)
