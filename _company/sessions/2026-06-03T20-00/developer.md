# PostgreSQL DB 스키마 V1 최종 검토 및 데이터 추출 모듈 로드맵 상세화

## 1. PostgreSQL DB 스키마 V1 최종 검토 (Schema Validation)

Researcher가 정의한 데이터 추출의 정확성과 확장성을 위해, 아래 스키마 구조를 최종 검토합니다.

**검토 결과:**
*   **컬럼 적합성:** 정의된 13개 컬럼은 연구과제 데이터 포괄성을 충족시키며, 'ALTIT 매칭 점수(AMS)' 계산에 필요한 모든 필수 입력 변수를 포함하고 있습니다.
*   **데이터 타입 적합성:** 각 컬럼의 데이터 타입(예: `VARCHAR` vs. `JSONB`)은 예상되는 비정형 데이터의 특성(기관별 상이한 메타데이터)을 고려하여 적절하게 설정되었습니다.
*   **AMS 로직 통합 검토:** `ams_weight` 컬럼의 설계는 향후 매핑 프레임워크와 연동될 수 있도록 유연하게 (예: JSONB 필드 또는 별도 테이블 참조) 설계되어, **Researcher의 매핑 전략 변경에 유연하게 대응 가능**합니다.

**개선/확인 사항 (Developer의 제안):**
1.  **관계형 구조 명확화:** `metadata`와 같이 변화 가능성이 높은 항목들은 일반 테이블보다는 **JSONB 컬럼**으로 분리하여 저장하는 것이 향후 스키마 마이그레이션 비용을 줄일 수 있습니다. (DB 성능 최적화 고려)
2.  **스키마 버전 관리:** DB 스키마 변경 이력을 추적하기 위해 `schema_version` 컬럼을 추가하여 버전 관리를 의무화해야 합니다.

## 2. 데이터 추출 모듈 구현 로드맵 상세화 (Implementation Roadmap)

PostgreSQL 스키마 V1을 기반으로, 데이터 추출 모듈 구현을 3단계로 나누어 상세화합니다.

### Phase 1: DB 초기 설정 및 기본 추출 (Foundation Setup)
**목표:** 안정적인 데이터 수집을 위한 인프라 구축 및 최소한의 핵심 데이터 추출 기능 구현.

| 단계 | 세부 활동 (Task) | 기술 스택/모듈 | 성공 기준 (Success Criteria) |
| :--- | :--- | :--- | :--- |
| **1.1 DB 생성 및 초기 마이그레이션** | PostgreSQL 인스턴스 구성, 스키마 V1 적용 및 초기 Seed 데이터 삽입. | `psycopg2` / Alembic (Migration) | DB 환경에서 스키마 V1이 오류 없이 생성 및 데이터가 정상 로드됨. |
| **1.2 모듈 A: 기본 API Connector** | 가장 안정적인 단일 타겟 기관(Top 1)의 공개 API 또는 정형화된 데이터 소스에 대한 **CRUD 추출 로직** 구현. | Python (requests), Pydantic (Validation) | Top 1 기관의 핵심 데이터가 성공적으로 DB에 삽입됨. |

### Phase 2: 타겟 기관별 확장 및 매핑 연동 (Scaling & Mapping Integration)
**목표:** Researcher가 정의한 타겟 기관별 접근 경로(1.1 단계에서 검증된)를 통합하고, 핵심 경쟁력인 'ALTIT 매칭 프레임워크'를 데이터 추출 과정에 주입합니다.

| 단계 | 세부 활동 (Task) | 기술 스택/모듈 | 성공 기준 (Success Criteria) |
| :--- | :--- | :--- | :--- |
| **2.1 모듈 B: 동적 추출 프레임워크** | 타겟 기관별로 상이한 데이터 포맷(JSON, XML, HTML)을 처리하기 위한 **Adapter 패턴** 구현. | Adapter Design Pattern, Dynamic Dispatching | 새로운 기관의 데이터 포맷이 추가되어도 핵심 추출 로직을 수정하지 않고 Adapter만 추가 가능해야 함. |
| **2.2 모듈 C: 매핑 프레임워크 통합 (핵심)** | 데이터 추출 단계에서, **타겟 기관별 매핑 프레임워크**를 입력으로 받아, 수집된 원천 데이터를 DB 스키마에 맞게 변환하고 `ams_weight`를 계산하는 로직 구현. | Custom Logic, AMS Calculation Engine | 추출된 데이터가 매핑 프레임워크의 규칙에 따라 정확하게 변환되고, AMS 점수가 실시간으로 계산되어 저장됨. |

### Phase 3: 안정화 및 자동화 (Stabilization & Automation)
**목표:** 전체 파이프라인의 견고성(Robustness) 확보 및 반복 작업을 자동화하여 장기 목표 달성 기반 마련.

| 단계 | 세부 활동 (Task) | 기술 스택/모듈 | 성공 기준 (Success Criteria) |
| :--- | :--- | :--- | :--- |
| **3.1 데이터 정제 파이프라인 완성** | 추출된 데이터의 품질 검증(Data Quality Check) 및 이상치 처리 로직 완성. | Data Validation Libraries, Error Handling | 데이터 품질 검증 실패 시, 명확한 에러 로그와 함께 재시도 또는 격리 처리 메커니즘 작동. |
| **3.2 전체 파이프라인 자동화** | Phase 1, 2의 모듈들을 통합하여 **CI/CD 환경에서 자동 실행**될 수 있도록 스크립트화 및 테스트 커버리지 확보. | Workflow Orchestration (e.g., Airflow/Prefect), Unit/Integration Tests | 전체 데이터 파이프라인이 수동 개입 없이 24시간 안정적으로 데이터를 수집/처리할 수 있음. |

**기술적 요구사항 요약:**
*   **핵심 기술:** Adapter Pattern (유연한 데이터 수집), 동적 스키마 매핑 로직, 트랜잭션 관리.
*   **연동 지점:** Phase 2의 모듈 C에서 Researcher가 확정한 **매핑 프레임워크 정의서**를 입력으로 받아 실행.
