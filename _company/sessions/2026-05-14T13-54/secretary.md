### 📊 병목 지점 식별 리스트 (Bottleneck Identification List)

**📌 목표:** 데이터 수집부터 최종 정제까지, 프로세스상의 잠재적 지연 및 오류 발생 지점을 식별하여 선제적으로 해결 방안을 모색합니다.

**🔍 핵심 분석 영역:**
1.  **데이터 수집 단계 (Researcher $\rightarrow$ Raw Data):** 외부 데이터 접근 및 추출의 안정성.
2.  **데이터 구조화 단계 (Raw Data $\rightarrow$ Structured Data):** 비정형 데이터를 DB/API 형식으로 변환하는 과정의 복잡성.
3.  **데이터 정제 및 검증 단계 (Structured Data $\rightarrow$ Clean Data):** 데이터의 품질 보장 및 일관성 유지.

**🚧 식별된 잠재적 병목 지점 (Potential Bottlenecks)**

| # | 단계 구분 | 잠재적 병목 지점 | 영향도 (High/Med/Low) | 근본 원인 분석 | 제안 액션 (Next Step Focus) |
| :---: | :--- | :--- | :---: | :--- | :--- |
| **1** | 데이터 수집 | **타겟 기관별 접근 경로의 비표준화** | High | 기관마다 요구하는 API 명세, 로그인 방식, 데이터 포맷이 상이하여 추출 모듈의 범용성 저하. | **Action:** 기관별 데이터 수집 요구사항(Need)의 표준화된 템플릿을 Developer와 공동으로 정의. |
| **2** | 데이터 구조화 | **복잡한 비정형 필드 매핑 오류** | High | 연구과제 정보(Title, Funding Source 등)가 기관별로 다른 용어로 명명되어, 자동 매핑 시 데이터 손실 또는 오류 발생. | **Action:** 핵심 필드에 대한 **용어 사전(Glossary)**을 구축하고, 매핑 규칙의 예외 처리 로직을 명확히 정의. |
| **3** | 데이터 정제 | **데이터 품질 검증 로직의 미흡** | Medium | 수집된 데이터의 형식 오류(Missing Value, Format Mismatch)에 대한 자동 검증 로직이 부재하여, 수동 검토로 인한 지연 발생. | **Action:** 데이터 정제 단계에서 **'필수 데이터 무결성(Integrity)'**을 체크하는 자동화된 검증 스크립트 구현. |
| **4** | 시스템 연동 | **API/DB 인터페이스의 불안정성** | Medium | Developer가 설계한 초기 스키마와 실제 데이터 추출 모듈 간의 인터페이스(Contract) 불일치로 인한 통합 실패 위험. | **Action:** 스키마 초안(Developer 산출물)을 기반으로, **인터페이스 테스트 케이스**를 즉시 작성하여 안정성 검증. |
