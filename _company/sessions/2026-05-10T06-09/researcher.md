## 🛠️ 실행 계획 (Phase별 데이터 수집 경로 및 요구사항 정의)

본 작업은 로드맵의 3단계에 맞춰, 각 단계별로 **'무엇을(Data)', '어디서(Source/Path)', '어떻게(Requirement)'** 수집할지 구체화하는 데 중점을 둡니다.

### Phase 1: 조사 및 범위 정의 (Phase 1 Data Requirements)
**목표:** 연구과제 조사를 시작하기 위한 **타겟 기관 리스트 확정** 및 **초기 검색 프레임워크 정의**.

| 요구사항 카테고리 | 세부 데이터/요구사항 | 현실성 검토 (Researcher 관점) | 핵심 산출물 (Definition) |
| :--- | :--- | :--- | :--- |
| **1. 타겟 기관 리스트** | 정부 부처별(예: 과기정통부, 산업부) 및 공공 연구기관(예: 출연연, 정부 산하 연구소)의 **실제 연구과제 등록/관리 시스템(DB/Portal)** 목록. | 각 기관별로 **'연구과제 공고/등록 사이트의 정확한 URL 및 접근 권한(API 또는 크롤링 난이도)'**을 식별해야 함. (단순 웹사이트가 아닌 실제 데이터 접근 경로 필요) | **타겟 기관별 최종 리스트 (URL, 연락처, 등록 시스템 특성 포함)** |
| **2. 핵심 연구 분야 키워드** | 현재 ALTIT KOREA의 기술 스택(예: AI, 빅데이터)과 연관된 **정부 과제 키워드 및 메타데이터** (Niche/Broad). | 단순히 키워드를 나열하는 것을 넘어, **'과제 분류 체계(Taxonomy)'**에 맞춰 키워드를 계층화해야 함. (예: AI > 생성형 모델 > 응용 분야) | **계층화된 연구 주제 키워드 맵 (Taxonomy Map)** |
| **3. 초기 검색 프레임워크** | 연구과제 등록/검색 시 적용할 **최적화된 검색 알고리즘(Query Logic)** 초안. | 데이터 추출의 효율성을 위해 **'필터링 조건(Filter Criteria)'** 정의가 필수적임. (예: 지원 분야, 연구 기간, 예산 규모 등) | **Phase 1 검색 프레임워크 초안 (Filter Set)** |

### Phase 2: 데이터 수집 및 검증 (Phase 2 Data Requirements)
**목표:** Phase 1에서 정의된 경로를 통해 **실제 연구과제 데이터(Raw Data)**를 확보하고, 그 데이터의 **신뢰도**를 검증합니다.

| 요구사항 카테고리 | 세부 데이터/요구사항 | 현실성 검토 (Researcher 관점) | 핵심 산출물 (Definition) |
| :--- | :--- | :--- | :--- |
| **1. 데이터 추출 모듈 명세** | Phase 1에서 확정된 URL/API 경로를 이용한 **대량 데이터 추출(Crawling/API Call)을 위한 기술적 인터페이스 명세**. | Developer 에이전트가 명세를 구체화할 수 있도록, **데이터 포맷(JSON/XML 등), 데이터 추출 빈도(Rate Limiting 고려)**를 명시해야 함. | **Phase 2 데이터 추출 API/크롤링 인터페이스 명세서** |
| **2. 데이터 정합성 검증 항목** | 수집된 연구과제 데이터(Title, Abstract, Funding Source 등)의 **데이터 품질 기준(Data Quality Check)**. | 데이터가 불완전하거나 비정형적일 가능성이 높으므로, **'누락률(Missing Data Rate)'** 및 **'비정형 데이터 정제 로직'**을 정의해야 함. | **데이터 품질 검증 체크리스트 (Validation Checklist)** |
| **3. 초기 데이터셋 샘플** | 검증된 데이터의 유효성을 입증하기 위한 **최소 규모의 샘플 데이터셋** 정의. | 실제 시스템 접근이 불가능할 경우, **가상의 구조(Schema)를 기반으로 샘플 데이터를 생성**하는 방안을 병행해야 함. | **최소 유효 데이터셋 스키마 (Schema Definition)** |

### Phase 3: 분석 및 제안서 준비 (Phase 3 Data Requirements)
**목표:** 수집된 데이터를 기반으로 **ALTIT KOREA의 강점과 기관 요구사항을 매핑**하여 경쟁 우위를 도출합니다.

| 요구사항 카테고리 | 세부 데이터/요구사항 | 현실성 검토 (Researcher 관점) | 핵심 산출물 (Definition) |
| :--- | :--- | :--- | :--- |
| **1. 강점-요구사항 매핑 모델** | ALTIT KOREA의 기술적 강점(Resource)과 타겟 기관이 요구하는 과제 특성(Need) 간의 **'Relevance 점수 산출 공식'**. | Business 에이전트가 정의할 'Relevance 점수 모델링 기준(sessions/2026-05-05T08-21/business.md)'을 **데이터 기반으로 구체화**해야 함. | **Relevance 점수 산출 알고리즘 (Formula & Weighting)** |
| **2. 성공/실패 패턴 분석 데이터** | 과거 채택된 연구과제와 미채택 과제의 **공통/차이점 데이터** (만약 확보 가능하다면). | 데이터가 없을 경우, **'성공 요인에 대한 이론적 가설(Hypothesis)'**을 정의하고, Phase 2의 데이터 수집 방향을 이 가설 검증에 맞추도록 수정해야 함. | **가설 기반 데이터 탐색 경로 (Hypothesis-Driven Path)** |
| **3. 제안서 구조 데이터** | 최종 제안서에 포함되어야 할 필수 항목 및 논리 흐름 (Phase 1/2 데이터와의 연결 고리). | 최종 산출물(제안서)의 구조가 **수집된 데이터의 흐름을 논리적으로 따라가도록** 설계해야 함. | **제안서 구조 매핑 맵 (Mapping to Data Flow)** |
