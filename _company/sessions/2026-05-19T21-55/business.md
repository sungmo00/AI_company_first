## 💰 Business 분석 및 최종 검토 산출물

**목표:** Researcher가 확보한 데이터 요구사항을 기반으로, 기술 리소스 매핑 및 대체 전략(전략 A) 설계의 최종 검토 및 통합을 진행하고, 확정된 로드맵에 필요한 기술적 리소스 요구사항을 최종 검증합니다.

**분석 범위:**
1. Researcher가 확정한 **Phase 3 (데이터 확보 및 초기 검증)**의 요구사항을 기반으로, 현재 설계된 기술 스택(Developer 산출물 참조)의 실행 가능성(Feasibility)을 최종 검토합니다.
2. **기술 리소스 매핑**의 완성도를 점검하고, 잠재적 리소스 부족 시나리오에 대비한 **대체 전략 (전략 A)**의 구체성 및 실행 가능성을 최종 검증합니다.
3. 전체 로드맵(SOP)에 필요한 **인력, 도구, 예산** 요구사항의 현실성을 검증하여, 실행 계획의 안정성을 확보합니다.

### 1. 기술 리소스 매핑 및 실행 가능성 최종 검토 (Feasibility Check)

**검토 항목:** 현재 설계된 기술 스택 대비 필요한 인력/도구의 현실성 및 리스크 평가.

| 구성 요소 | 요구사항 (Researcher 기반) | 현재 설계된 스택/리소스 | 실행 가능성 점수 (1-5, 5=최상) | 리스크 수준 | 권고 사항 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **데이터 추출 모듈 (Phase 2)** | 안정적인 API/크롤링 구현 및 데이터 정제 로직. (Developer 산출물 참조) | PostgreSQL 스키마 초안, API 인터페이스 명세. | 4/5 | 중간 | **Developer의 초기 구현 검토 완료 후, PoC 환경에서 API 응답 지연 시간(Latency) 측정 필수.** |
| **AMS 가중치 적용 로직 (Phase 2)** | 데이터 기반의 타당성 검토 및 모델링. | AMS 가중치 적용 로직 상세 기준서 (Developer 산출물 참조). | 4/5 | 중간 | **Business의 재검토(모델링 정확도)가 필수적임. 가중치 결정 근거의 정량화 수준 확인.** |
| **인력 리소스 (Phase 1, 2)** | 데이터 엔지니어링(DB/API 연동) 및 백엔드 개발 전문성. | Researcher/Developer 협업 구조 기반 인력 분배안. | 3/5 | 높음 | **Mid-Level 이상의 전문성을 요구하는 영역이 집중됨. 초기 인력 확보 시 Critical Path로 설정.** |
| **기술 스택 업그레이드 예산 (Contingency)** | 잠재적 기술 부채 발생 시 대응을 위한 예비비. | Developer 산출물에서 산출된 Contingency 규모. | 3/5 | 중간 | **예산 책정의 근거(Top N 리스크 시나리오)를 명확히 문서화해야 함. 추정치보다 20% 상향 조정 권고.** |

**결론:** 현재 기술 스택은 로드맵의 **핵심 기능 구현(Phase 2)** 측면에서는 실행 가능하나, **인력 확보 및 기술적 리스크 관리** 측면에서 중간 수준의 위험이 존재합니다.

### 2. 대체 전략 (전략 A) 최종 검증 및 통합

**목표:** 리소스 부족 또는 기술적 난항 시, 실행 경로를 변경할 수 있는 **대체 전략 (전략 A)**의 구체성과 실행 가능성을 최종 검증하고 통합합니다.

| 시나리오 | 발생 원인 (리스크) | 전략 A (대체 방안) | 실행 난이도 | 권고 결정 (A/B) | 근거 숫자/논리 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Scenario 1: 데이터 소스 접근 실패** | Phase 1에서 타겟 기관의 API/웹 접근이 비협조적이거나 불가능할 경우. | **전략 A1: 2차 데이터 소스 탐색 (파트너십 중심)**. 특정 연구기관 대신, 해당 분야의 공공 데이터 포털 또는 산업 협회 데이터를 우선 확보하여 PoC를 진행. | 중간 | **A (선택)** | 초기 단계에서 데이터 확보의 '속도'가 '완벽한 소스'보다 중요함. 3주 내 PoC를 위한 최소 데이터 확보 목표 설정. |
| **Scenario 2: 기술 스택의 과도한 복잡성** | Developer가 예상치 못한 기술적 난이도로 인해 Phase 2 구현 지연 발생. | **전략 A2: MVP 범위 축소 (Scope Reduction)**. AMS 가중치 모델의 복잡도를 초기 버전에서 단순화(Rule-Based Model → Simple Regression)하여 핵심 가치만 선행 출시. | 낮음 | **A (선택)** | '수익화 모델 1개 가설 검증' 목표 달성을 위해, MVP 범위 축소는 시간 대비 성과(Time-to-Market)를 극대화함. |
| **Scenario 3: 인력 리소스 부족** | 핵심 데이터 엔지니어링 인력 확보 실패. | **전략 A3: 외주/단기 계약 활용 (Fixed Price)**. 내부 채용 대신, 특정 Phase 2 마일스톤에 대해서만 단기 계약(Fixed Price)을 통해 리소스를 투입. | 중간 | **A (선택)** | 장기적인 내부 인력 확보보다 단기적 목표 달성이 우선이므로, 초기 리스크에 대한 비용을 명확히 산정하고 실행. |

**통합 결정:**
* **기술 스택 조정:** Strategy A2 (MVP 범위 축소)를 채택하여 초기 시장 검증 속도를 높입니다.
* **리스크 관리:** Strategy A1 (2차 데이터 소스 탐색)을 병행하여, 단일 실패 지점(Single Point of Failure)을 제거합니다.
* **리소스 투입:** Strategy A3 (외주/단기 계약)을 비상 계획으로 확정하고, 현재 리소스 투입은 내부 인력 중심(Feasibility 4/5)으로 진행합니다.

### 3. 최종 기술 리소스 요구사항 요약 (Actionable Items)

다음은 확정된 로드맵(SOP)을 실행하기 위해 즉시 요구되는 **최종 리소스 목록**입니다.

1. **인력 (Critical Path):** 데이터 엔지니어링 전문성 보유자 1명 (Phase 2 집중).
2. **기술 환경:** PostgreSQL 기반의 데이터 레이크/웨어하우스 환경 구축 완료 (Developer 협업).
3. **모델링 검증:** AMS 가중치 모델의 '정량적 타당성 보고서' (Business 검토 완료 후 제출).
4. **예산 (Contingency):** 리스크 시나리오별 예산(Low/Mid/High)을 명확히 구분하여 재제안.
