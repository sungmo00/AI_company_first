### 데이터 추출 프로세스 정의서 (SOP) - 최종 워크플로우

**프로젝트 목표:** 정부 및 공공기관의 연구과제 데이터를 체계적으로 수집, 정제, 그리고 내부 DB(스키마 V1)에 매핑하는 자동화된 파이프라인 구축.

**핵심 구성 요소:**
1. **데이터 수집 (Collection):** 타겟 기관별 데이터 확보 전략 및 실제 추출 로직 정의.
2. **데이터 정제 (Refinement):** 수집된 원시 데이터의 품질 보증 및 표준화.
3. **데이터 매핑 (Mapping):** 정제된 데이터를 DB 스키마 V1의 구조에 맞게 변환 및 로직 구현.

#### **Phase 1: 데이터 수집 (Collection)**
**목표:** 정의된 타겟 기관별/분야별 연구과제 데이터를 안정적으로 확보하는 경로 및 추출 로직을 확정합니다.

| 단계 | 세부 작업 내용 | 담당 에이전트 | 산출물 (Output) | 성공 기준 (KPI) | 비고/검토 사항 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **1.1 타겟 기관/API 확정** | Researcher가 정의한 '최우선 타겟 5개 기관'별로 데이터 접근 가능한 모든 경로(공식 API, 공개 데이터 포털, 웹 크롤링 대상 URL)를 최종 확정. | Researcher | `Target_Institution_Access_Map.json` (기관별 접근 경로 및 난이도 평가 포함) | Top 5 기관의 접근 경로 100% 확정 및 난이도 평가 완료. | API 인증/Rate Limit 정책 검토 필수. |
| **1.2 데이터 추출 시나리오 설계** | 각 경로별로 필요한 데이터 항목(Schema Definition 기반)을 식별하고, 실제 데이터를 추출하기 위한 Step-by-Step 크롤링/API 호출 시나리오를 구체화. | Researcher | `Extraction_Scenario_Drafts` (기관별 추출 시나리오 초안) | 각 기관별 최소 3가지 이상의 성공적인 추출 시나리오 초안 확보. | 데이터 정합성 유지를 위한 초기 필터링 로직 포함 여부 결정. |
| **1.3 초기 데이터 수집 (Pilot Run)** | 가장 접근성이 높은 경로를 선정하여 최소량의 샘플 데이터를 추출하고, 수집된 데이터의 포맷 및 누락 항목을 검증. | Researcher / Developer (협업) | `Pilot_Data_Sample` 및 초기 데이터 포맷 보고서 | 샘플 데이터 추출 성공률 80% 이상. 데이터 형식 불일치 건수 5% 미만. | DB 스키마 V1과의 초기 매핑 가능성 사전 검토. |

#### **Phase 2: 데이터 정제 (Refinement)**
**목표:** Phase 1에서 수집된 원시 데이터를 DB 스키마 V1에 적합하도록 일관되고 신뢰할 수 있는 형태로 변환하고 정제합니다.

| 단계 | 세부 작업 내용 | 담당 에이전트 | 산출물 (Output) | 성공 기준 (KPI) | 비고/검토 사항 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **2.1 데이터 표준화 (Normalization)** | 수집된 비정형 텍스트/숫자 데이터를 DB 스키마 V1의 데이터 타입(예: 날짜 형식, 숫자 범위)에 맞게 강제 변환 및 정규화. | Developer | `Data_Normalization_Rules.yaml` (필수 변환 규칙 정의) | 데이터 타입 불일치 오류 발생률 0%. 정규화 로직 명확화. | 특수 문자 처리, 결측치(Null) 값의 대체 전략 정의 필요. |
| **2.2 데이터 유효성 검증 (Validation)** | 비즈니스 로직 기반의 유효성 검사 수행. (예: 과제명 길이 제한, 필수 필드 누락 여부, 중복 데이터 탐지) | Developer | `Validation_Test_Cases` (테스트 케이스 및 오류 처리 로직) | 유효성 검사 로직에 대한 모든 테스트 케이스 커버리지 100%. | 'ALTIT 매칭 점수(AMS)' 계산에 필요한 데이터의 정확성 확보. |
| **2.3 메타데이터 주입** | 수집된 데이터에 내부 추적 및 평가를 위한 필수 메타데이터(수집 일시, 출처 기관 ID, 수집 난이도 점수)를 추가 주입. | Developer | 정제된 데이터셋 (메타데이터 포함) | 메타데이터 누락 없이 모든 레코드에 주입 완료. | 이 단계에서 DB 스키마 V1의 메타데이터 필드 매핑 최종 확인. |

#### **Phase 3: 데이터 매핑 (Mapping)**
**목표:** 정제된 데이터를 DB 스키마 V1의 최종 구조에 맞추어 정확하게 매핑하고, 비즈니스 로직(AMS 계산 등)을 적용하여 최종 데이터셋을 생성합니다.

| 단계 | 세부 작업 내용 | 담당 에이전트 | 산출물 (Output) | 성공 기준 (KPI) | 비고/검토 사항 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **3.1 스키마-데이터 매핑 로직 설계** | Phase 2의 정제된 데이터 필드와 DB 스키마 V1의 각 컬럼 간의 일대일/다대일 매핑 로직을 상세하게 정의. | Developer | `DB_Mapping_Logic_V1.md` (컬럼별 매핑 상세 설명 및 변환 함수 정의) | 모든 DB 컬럼에 대한 명확한 소스 필드 및 변환 로직 정의 완료. | **'ALTIT 매칭 점수(AMS)' 가중치 적용 로직의 데이터 기반 타당성 최종 검토 및 확정.** |
| **3.2 ETL 파이프라인 구현** | Phase 1, 2에서 정의된 추출 및 정제 로직을 기반으로 실제 데이터베이스 삽입(Insert) 또는 업데이트(Upsert)를 수행하는 ETL 파이프라인 코드를 구현. | Developer | `ETL_Pipeline_Code` (DB 연동 및 매핑 로직 포함) | ETL 파이프라인 실행 시 데이터 무결성 검증 통과. | DB-SOP 간의 연동 오류 발생 지점 식별 및 디버깅 준비. |
| **3.3 최종 검증 (End-to-End Test)** | 전체 파이프라인(Collection -> Refinement -> Mapping)을 End-to-End로 실행하여, 최종적으로 생성된 DB 데이터의 정확성을 검증. | Researcher / Developer | `End_to_End_Verification_Report` (최종 데이터 정확성 보고서) | 최종 데이터셋의 정확도 99% 이상 확인. | 이 단계에서 개발/연구 간의 최종 산출물 검토 완료. |
