### 📜 연구과제 조사 로드맵 실행 SOP (최종 확정 버전)

**궁극적 목표:** 정부 및 공공기관이 등록한 연구과제 데이터를 체계적으로 수집, 분석, 가공하여 '정부 및 공공기관 연구과제 조사 데이터베이스'를 구축한다.

#### **Phase 1: 환경 설정 및 기초 데이터 수집 (Foundation & Scoping)**

**목표:** 연구과제 데이터의 포괄적인 수집 범위(Scope)를 정의하고, 초기 데이터 수집을 위한 필수 메타데이터 및 기본 정보를 확보한다.

| 세부 단계 | 목표 (Objective) | 데이터 추출 항목 (Schema Definition - Phase 1) | 검증 기준 (Validation Criteria) | 출처/접근 경로 (Initial Target) |
| :--- | :--- | :--- | :--- | :--- |
| **1.1 타겟 기관 식별** | 연구과제 등록이 활발한 최우선 정부 부처 및 공공 연구기관 Top 5를 최종 확정한다. | 기관명, 공식 웹사이트 URL, 담당 부서(연구지원팀 등), 등록된 연구과제 유형 분류. | 5개 기관 리스트의 공식 웹사이트 및 데이터 수집 가능 여부 확인 완료. | Researcher 개인 메모리 (2026-05-05) 기반으로 확정된 최우선 타겟 리스트. |
| **1.2 기본 메타데이터 정의** | 수집할 모든 연구과제에 공통적으로 필요한 핵심 정보 항목을 정의한다. | 과제ID (고유 식별자), 과제명(제목), 등록일자, 연구비 규모(예상 범위), 최종 선정 여부(Status). | 정의된 항목들이 향후 DB 설계의 기본 키 및 필수 필드로 사용될 수 있는지 기술적 타당성 검토. | Researcher 개인 메모리 (2026-05-05)의 Schema Definition 기반. |
| **1.3 초기 데이터 추출 시나리오** | 1.1에서 확정된 기관별로, 최소한의 공개 API 또는 크롤링을 통해 초기 데이터 추출 시나리오를 정의한다. | 추출 대상 항목 목록, 각 항목의 예상 포맷(JSON/HTML), 접근 난이도 평가 점수 (1~5점). | 정의된 시나리오가 실제 웹/API 구조를 기반으로 실행 가능함(Feasibility Check)을 70% 이상 만족해야 함. | Researcher 개인 메모리 (2026-05-05)의 API/웹 접근 경로 분석 결과 기반. |

#### **Phase 2: 심층 데이터 수집 및 정규화 (Deep Collection & Normalization)**

**목표:** Phase 1에서 정의된 범위 내에서 실제 연구과제 상세 데이터를 수집하고, 데이터의 일관성(Normalization)을 확보한다.

| 세부 단계 | 목표 (Objective) | 데이터 추출 항목 (Schema Definition - Phase 2) | 검증 기준 (Validation Criteria) | 출처/접근 경로 (Target) |
| :--- | :--- | :--- | :--- | :--- |
| **2.1 상세 정보 추출** | Phase 1에서 정의된 기관별로, 실제 연구과제 상세 내용(연구 내용, 참여 인력, 예산 세부 내역)을 추출한다. | 연구내용(요약/본문), 주요 연구 인력 및 소속, 세부 예산 항목별 내역(항목명, 금액). | 추출된 데이터의 양적 충족도 (최소 80% 이상) 및 정보의 누락 여부(Null Count)를 검증. | Phase 1에서 확정된 각 기관별 데이터 수집 시나리오(Step-by-Step) 실행. |
| **2.2 데이터 정규화** | 추출된 비정형 데이터를 표준화된 형식(JSON/CSV)으로 변환하고, 데이터 타입 오류를 수정한다. | 표준화된 필드 매핑 테이블 (Source Field $\rightarrow$ Target Field), 데이터 타입 변환 규칙. | 정규화 과정에서 발생하는 데이터 손실률(Data Loss Rate)을 5% 미만으로 유지해야 함. | Developer가 설계할 PostgreSQL 스키마 초안과의 정합성 검토를 병행. |
| **2.3 데이터 품질 점검** | 수집된 데이터의 신뢰도를 평가하여, 불완전하거나 오류가 심각한 데이터를 식별한다. | 데이터 품질 점수 (Data Quality Score, 1~10점), 오류 유형 분류 (예: 형식 오류, 내용 불일치). | 데이터 품질 점수가 평균 7.5점 이상이어야 하며, 심각 오류(Critical Error) 비율은 1% 미만이어야 함. | 자체 개발한 데이터 품질 체크리스트 적용. |

#### **Phase 3: 분석 준비 및 라이브러리 구축 (Analysis Readiness & Library)**

**목표:** 수집된 정제된 데이터를 기반으로, 향후 연구과제 제안서 작성 및 트렌드 분석에 즉시 활용 가능한 형태로 데이터베이스를 구축한다.

| 세부 단계 | 목표 (Objective) | 데이터 추출 항목 (Schema Definition - Phase 3) | 검증 기준 (Validation Criteria) | 출처/접근 경로 (Target) |
| :--- | :--- | :--- | :--- | :--- |
| **3.1 분석용 데이터 모델링** | 최종적으로 연구과제 제안 및 트렌드 분석에 필요한 가공된 데이터 모델을 설계한다. | 연구 주제 카테고리(Taxonomy), 기술 키워드 태그, 성공/실패 예측 지표(Metric). | 설계된 모델이 향후 트렌드 리포트 발행에 필요한 모든 분석 요소를 포함해야 함을 입증. | 1차 자료 라이브러리 구축 목표에 부합하는 구조인지 확인. |
| **3.2 데이터 통합 및 저장** | Phase 1, 2에서 수집/정규화된 데이터를 최종 데이터베이스(PostgreSQL)에 로드한다. | 최종 DB Schema (Phase 1, 2의 모든 필드를 통합), 데이터 로드 성공 로그. | 전체 데이터셋이 DB에 오류 없이 성공적으로 적재되었으며, SQL 쿼리 테스트를 통과해야 함. | Developer가 설계할 최종 PostgreSQL 스키마와 100% 일치해야 함. |
| **3.3 초기 활용 테스트** | 구축된 데이터베이스를 사용하여 최소한의 분석 쿼리(예: 특정 기술 분야별 과제 수 집계)를 실행한다. | 테스트 쿼리 성공 여부, 응답 시간(Latency). | 핵심 분석 쿼리가 정의된 SLA(Service Level Agreement) 시간 내에 응답해야 함. | 자체 검증 쿼리셋 사용. |
