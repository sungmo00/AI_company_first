### 🔗 데이터 추출 모듈 정의 (초안)

각 타겟 기관에 대해 필요한 핵심 데이터 컬럼(Schema Definition의 기반)과 추출 전략을 정의합니다.

**핵심 데이터 컬럼 (공통 요구사항):**
*   `project_id`: 연구과제 고유 식별자
*   `institution`: 과제를 발주/수행한 기관명
*   `title`: 연구과제 제목
*   `focus_area`: 핵심 기술/분야 (AI, 빅데이터 등)
*   `funding_source`: 지원 주체 (정부, 재단 등)
*   `application_deadline`: 공고 마감일
*   `status`: 현재 상태 (공고, 선정, 완료 등)
*   `source_url`: 원본 공고 페이지 링크 (출처 링크 필수)

**모듈 정의 상세:**
*   **Type A (API 기반):** 기관에서 공식적으로 제공하는 데이터 API를 활용하여 **구조화된 JSON/XML 형태**로 데이터를 직접 수신하는 방식. (가장 이상적)
*   **Type B (웹 크롤링 기반):** 정기적인 웹페이지 업데이트를 가정하고, Selenium 또는 BeautifulSoup을 사용하여 HTML 구조에서 필요한 데이터를 파싱하는 방식. (유연하지만 불안정)
*   **Type C (비정형/수동):** API나 구조화된 데이터가 없을 경우, 주기적인 수동 검토 및 데이터 입력(Human-in-the-Loop)을 병행하는 방식. (최후의 수단)

**Researcher 제언:**
Developer 에이전트와 협력하여, **타겟 기관별로 Type A를 최우선으로 시도**하고, Type B는 백업 플랜으로 정의해야 합니다. 특히 난이도가 높은 4번 타겟(KIST 등)에 대해서는 Type C의 비중을 높게 잡아 **'인증된 접근 경로 확보 전략'**을 별도로 설계해야 합니다.
