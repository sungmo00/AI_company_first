### 1. AMS 가중치 확정 로드맵 (Phase 3 진입 기준)

본 로드맵은 'ALTIT 매칭 점수(AMS)'를 기반으로, 연구과제 제안 성공 확률을 극대화하기 위한 단계별 가중치 설정 및 데이터 확보 전략을 명시합니다.

| 단계 (Phase) | 목표 | 주요 측정 지표 (KPIs) | AMS 가중치 구성 요소 (예시) | 핵심 데이터 요구사항 | 예상 소요 기간 | 산출물 의존성 |
| :---: | :--- | :--- | :--- | :--- | :--- | :--- |
| **Phase 1: 기초 탐색** | 타겟 기관 및 연구 분야의 광범위한 매핑 기반 구축 | 타겟 기관/분야 적합도 점수 (Relevance Score) | 기관의 연구 주제 일치율 (50%), 분야의 정책적 중요도 (30%), 기술적 난이도 예측 (20%) | 기관별 연구 포트폴리오 데이터, 정책 분류 코드 | 4주 | Researcher의 초기 기관/분야 매핑 프레임워크 초안 |
| **Phase 2: 심층 분석** | 잠재적 연구 과제의 구체적인 기회 식별 및 우선순위 지정 | 과제 채택 가능성 예측 점수 (Viability Score) | 기술적 혁신성 (40%), 정부 지원 적합성 (35%), 경쟁사 활동 벤치마킹 결과 (25%) | 과제별 기술 요구사항 상세 스키마, 경쟁사 유사 과제 데이터 | 6주 | Phase 1 결과물, 경쟁사 활동 분석 리포트 |
| **Phase 3: 제안 최적화** | 정부/공공기관의 요구사항에 완벽히 부합하는 제안서 완성 | 최종 성공 확률 (Success Probability) | 연구 수행 역량 (45%), 제안서 완성도 (30%), 리소스 매칭 적합성 (25%) | 내부 역량 데이터, 기술/예산 매핑 결과 (Business 에이전트 산출물) | 지속적 | Phase 2 결과물, Business 에이전트의 리소스 매핑 데이터 |

**👉 AMS 가중치 확정 원칙:**
*   Phase 1에서는 **'연구 분야의 적합성'**에 가장 높은 가중치를 부여하여 광범위한 탐색을 유도합니다.
*   Phase 2에서는 **'기술적 혁신성 및 지원 적합성'**에 비중을 높여 성공 가능성이 높은 과제를 선별합니다.
*   Phase 3에서는 **'내부 역량과 외부 요구사항의 완벽한 일치(리소스 매칭)'**에 가장 높은 가중치를 두어 제안의 실현 가능성을 최종 검증합니다.

### 2. Business 에이전트 활용을 위한 데이터 항목 (컬럼 정의) 명세서

본 섹션은 Business 에이전트가 리소스 매핑 및 예산 책정 작업을 수행할 때 필요한 핵심 데이터 항목(컬럼)의 정의입니다. Researcher가 수집하는 기초 데이터와 Business 에이전트가 매핑할 내부/외부 리소스 데이터를 구분하여 설계했습니다.

#### 2.1. 연구 과제 데이터 항목 (Researcher 산출물 연계)

| 컬럼명 (Column Name) | 데이터 타입 (Data Type) | 설명 (Description) | 필수 여부 | 소유 에이전트 | 연계 데이터 소스 |
| :--- | :--- | :--- | :---: | :--- | :--- |
| `project_id` | String | 연구 과제의 고유 식별자 | 필수 | Researcher | 정부/기관 데이터베이스 |
| `target_agency` | String | 해당 과제를 발주한 정부 부처 또는 기관명 | 필수 | Researcher | 정부/기관 데이터베이스 |
| `research_field` | String (Array) | 연구가 속하는 핵심 기술/분야 (예: AI, Quantum Computing) | 필수 | Researcher | 연구 분야 매핑 프레임워크 |
| `required_tech` | String (Array) | 과제 수행에 필수적인 핵심 기술 목록 | 필수 | Researcher | Project Schema 정의 |
| `priority_score` | Float (0.0 - 1.0) | 해당 과제의 전략적 우선순위 점수 (Phase별 산출) | 필수 | Researcher | AMS 가중치 계산 결과 |
| `funding_potential` | Integer | 예상되는 연구비 규모 (단위: 천원) | 필수 | Researcher | 정부/기관 데이터베이스 |
| `alignment_metric` | Float (0.0 - 1.0) | 내부 역량과의 기술/인력 매칭 적합도 (Phase 3 핵심 지표) | 필수 | Business | 내부 역량 데이터 + Researcher 데이터 |

#### 2.2. 리소스 매핑 및 예산 데이터 항목 (Business 에이전트 산출물 연계)

| 컬럼명 (Column Name) | 데이터 타입 (Data Type) | 설명 (Description) | 필수 여부 | 소유 에이전트 | 연계 데이터 소스 |
| :--- | :--- | :--- | :---: | :--- | :--- |
| `resource_type` | String | 필요한 리소스 유형 (예: 인력, 장비, 소프트웨어 라이선스) | 필수 | Business | 리소스 정의 테이블 |
| `required_skill` | String | 해당 리소스를 수행하는 필수 전문 기술/역량 | 필수 | Researcher | Required_Tech (2.1) |
| `internal_capacity` | Integer | 현재 보유하고 있는 해당 역량의 내부 인력/장비 수량 | 필수 | Business | 내부 자원 현황 DB |
| `gap_analysis` | String | 내부 역량과 요구사항 간의 차이점 (Gap) 상세 설명 | 필수 | Business | 내부 역량 데이터 vs. Required_Tech |
| `resource_cost_estimate` | Float | 해당 리소스를 확보/충족시키기 위한 예상 비용 (단위: 원) | 필수 | Business | 기술 스택 업그레이드 예산 (Developer 산출물 연계) |
| `risk_factor` | String | 해당 리소스 확보 실패 시 프로젝트에 미치는 위험도 (High/Medium/Low) | 필수 | Business | Contingency 계획 데이터 |
