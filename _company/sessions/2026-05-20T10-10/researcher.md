#### 2. 데이터 추출 프로세스 세부 단계 정의 (Data Extraction Workflow Detail)

**목표:** Phase 3의 실행을 위한 구체적인 기술 및 운영 단계를 정의합니다. (Developer와의 협업을 전제로 함)

**세부 단계:**

1.  **Input 정의 (Phase 1 결과 기반):**
    *   입력: 확정된 '기관별/분야별 검색 가이드라인 초안' (Phase 2 산출물).
    *   요구사항: 각 기관별 API 엔드포인트(또는 크롤링 대상 URL), 필요한 파라미터, 데이터 추출 빈도 정의.
2.  **Extraction Module Design (Developer 협업):**
    *   설계: Pydantic 스키마(`ResearchProjectSchema`)와 최종 매핑을 기반으로, 각 데이터 필드(13개 컬럼 포함)별로 추출 로직을 명시화합니다.
    *   가중치 적용: 'ALTIT 매칭 점수(AMS)' 계산에 사용될 각 필드별 가중치($W_i$) 및 관련 데이터 소스 정의.
3.  **Data Acquisition Execution (Researcher/Developer):**
    *   실행: 정의된 경로에 따라 데이터 추출 모듈을 실행합니다. (Error Handling 및 Rate Limiting 메커니즘 포함 필수).
    *   Validation: 추출된 데이터가 `ResearchProjectSchema`에 맞는지 즉각적으로 검증하는 로직을 삽입합니다.
4.  **Data Cleansing & Normalization (Researcher):**
    *   정제: 비정형 데이터(텍스트)의 표준화(토큰화, 정규화) 및 결측치 처리 규칙 적용.
    *   Integrity Check: 추출된 데이터의 일관성(예: 동일 과제에 대한 상이한 명칭 방지)을 검사합니다.
5.  **Output Generation (Phase 4 준비):**
    *   포맷팅: 정제된 데이터를 Secretary가 보고서 작성을 용이하게 할 수 있는 구조화된 형식(예: JSON, CSV)으로 최종 변환합니다.
    *   Report Generation Hook: 보고서 작성을 위한 메타데이터(출처, 추출 시점 등)를 각 데이터 레코드에 태깅합니다.
